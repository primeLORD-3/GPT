# Proxy Chat Studio 使用文档

## 1. 运行项目

```bash
npm install
npm start
```

访问：`http://localhost:3000`

---

## 2. 参数怎么填（最重要）

### 方案 A：分开填写（推荐）

- `API Base URL`：`https://your-proxy.example.com`
- `API Path`：`/v1/chat/completions`
- `Model`：例如 `gpt-4o-mini`
- `API Key`：你的 key

### 方案 B：完整 URL 直接填到 API Path

- `API Base URL`：可留空
- `API Path`：`https://your-proxy.example.com/v1/chat/completions`

> 这两种方案二选一，不要重复拼接。

---

## 3. 聊天与上下文功能

- **发送消息**：输入后点击“发送”或 `Ctrl/Cmd + Enter`。
- **系统提示词**：左侧 `System Prompt`，修改后立即生效并自动保存。
- **插入 assistant 消息**：点击“插入 assistant 消息”按钮。
- **导出上下文**：点击“导出上下文”，下载 JSON。
- **清空上下文**：点击“清空上下文”。
- **自动存档**：每次输入/发送后都会自动写入 `localStorage`。

---

## 4. 常见报错与处理

### 报错：上游返回了非 JSON 数据

原因：通常是接口地址填错，或者网关返回了 HTML 页面（登录页、404 页面）。

处理：
1. 检查 `API Base URL` 与 `API Path` 是否按上面的 A/B 方案填写。
2. 确认最终地址可被 POST 且兼容 OpenAI chat completions。
3. 检查是否缺少鉴权导致跳转到网页。

### 报错：缺少必要参数 model/messages

原因：`Model` 为空，或请求数据不是合法消息数组。

处理：确保 `Model` 已填写；正常通过界面发送即可自动构造 `messages`。

### 报错：上下文超过 50MB

原因：历史消息太长。

处理：导出后清空上下文，或删除无用消息再发送。

---

## 5. “在哪个文件夹更改 assistant？”

- **普通使用者**：不用改文件，直接在页面点击“插入 assistant 消息”。
- **开发者改逻辑**：修改 `public/app.js`：
  - `insertAssistantMessageManually()`：控制“插入 assistant 消息”行为
  - `appendMessage('assistant', ...)`：assistant 消息入库位置
  - `state.systemPrompt`：默认系统提示词
